## 3. 全文论证链与章节交接

**观察失败 → 明确参照与标签 → 解释检测依据 → 建立评价协议 → 比较缓解机制 → 按同一协议复评 → 讨论收益、代价与剩余问题。**

| 章节 | 必须给出的信息 | 交给下一章的问题 |
|---|---|---|
| §1 Introduction | 动机、文本范围、RQ1–RQ3；Fig.1 后接 Fig.2 | 这些示例中的“错”究竟相对于什么？ |
| §2 Concepts and Scope | §2.1 世界事实性/来源忠实性；§2.2 标签映射与发展脉络 | 标签确定后，检测器可以取得哪些证据？ |
| §3 Detection Methods | §3.1 外部证据；§3.2 采样一致性；§3.3 内部信号；比较访问权限、监督和局限 | 得到标签或风险分数，不代表判断正确：怎样验证？ |
| §4 Benchmarks and Evaluation | §4.1 生成内容评价；§4.2 检测器评价；基准、指标、标注粒度与可比条件 | 评价标准明确后，哪些干预能改善同一目标？ |
| §5 Mitigation Methods | §5.1 训练对齐；§5.2 检索提示；§5.3 解码干预；§5.4 修正拒答 | 收益是否依赖特定模型、来源、裁判或较高拒答率？ |
| §6 Analysis and Future Work | 将 §3–§5 的证据按可比条件综合；回答检测局限、干预权衡和研究缺口 | 哪些结论足以保留，哪些仍需验证？ |
| §7 Conclusion | 简洁回答 RQ1–RQ3，限定适用范围 | 不新增方法、数据、论点或未经讨论的未来方向 |

主文顺序调整为“检测—评估—缓解”，与题目顺序及图编号保持一致。§6 可以回指前文证据，但不再逐项重讲算法。方法段落统一采用“目标/假设—机制—证据—适用条件—局限”；跨论文比较需要核对实际实验条件。

## 4. 定义与示例的闭环

- **世界事实性**：相对于外部世界及选定核验资源；资源可能过期、冲突或不完整。
- **来源忠实性**：相对于任务指定的文档、对话或检索上下文。忠实复述错误来源仍可能不符合世界事实。
- “未被支持”有时被文献用作所有非蕴含输出的总称，有时只指来源既未支持也未否定的内容。正文必须明确采用的标签协议，不能默认它与“矛盾”天然互斥。
- Fig.1 的绿色特指没有足够来源依据的新增信息；粉色/蓝色分别标示数值与关系矛盾。这是示例的视觉编码，不是相同层级的完整分类树，也不能用绿色代表正确。
- 咖啡馆与大学来源：证据未说明，合适结论是“来源无法确认”，不能擅自改成“不存在咖啡馆”或“并非来自大学”。
- 书本数量和楼层：来源明确给出 12,000 / second floor；输出的 20,000 / first floor 与来源相矛盾。
- 摘要来源明确到货 Monday、整理 Tuesday、编目 Wednesday。输出分别改错日期和数量、补入大学来源、颠倒整理与编目顺序。蓝色例子不再同时虚构不存在的编目事件。
- 所有示例均由作者构造，用于解释概念；不得冠以具体模型名、性能数值或实验结论。

§2 需要从原文献补足 Fig.1 未覆盖的世界事实性、不可核验和标签协议差异。Fig.1 无需承担整个研究领域的覆盖任务。

## 5. Fig.3 与 Table 1 的逐行对应

| Table 1 基准 | Fig.3 入口 | 解释边界 |
|---|---|---|
| TruthfulQA | Gen → World factuality | MC 是另一个回答任务，不等于幻觉检测；不要与 Dis 的 accuracy 混为一谈 |
| HaluEval | Dis → Response/sentence classification | 任务、构造样本和通用回答子集需分开报告 |
| ANAH | Dis → Response/sentence classification | 生成式标注器也是输出幻觉标签的检测器，架构不会自动使任务变成 Gen |
| RAGTruth | Dis → Error-span localization | 也包含 response-level classification；两种粒度应分别报告 |
| ExpertQA | Gen → World factuality / Source faithfulness | 正确性与引用支持分别分析，不以有引用等同于答案正确 |
| TofuEval | Gen → Source faithfulness；Dis → Classification | 生成摘要的错误率与检测器 balanced accuracy 是不同评价对象 |
| HALoGEN | Gen → World factuality | 表中规模为完整九领域套件；正文只讨论文本相关部分 |
| FaithBench | Gen → Source faithfulness；Dis → Classification | Gen 仅指已标注摘要的质量分析；挑战集有选择偏差，不估计一般生成分布的幻觉率 |
| FactBench | Gen → World factuality | 使用论文版本快照；事实精确率不代表答案完整性 |

Fig.3 的叶节点列出评价维度及指标族，Table 1 才列具体基准的报告指标。不能据此认定同枝所有基准共享完全相同的公式、标注或数据划分。FActScore、VeriScore 等是评价方法，不能仅凭名称放进“数据集规模”列。

## 6. Fig.4 与子节的对应，以及反馈闭环

Fig.4 横向按流水线位置组织，§5 按干预机制组织；两者不要求一列等于一节。

| Fig.4 代表机制 | §5 主讲位置 | 交叉联系 |
|---|---|---|
| Faithful data / factuality alignment | §5.1 训练与对齐 | FaithDial、Self-Alignment、FactAlign；训练如何影响最终输出仍需 §4 评价 |
| Adaptive retrieval / resolve conflicts | §5.2 检索与提示 | Self-RAG 也涉及训练；Astute RAG 涉及参数知识与外部证据冲突 |
| Representation editing / attention control / contrastive decoding | §5.3 解码与干预 | TruthX、Lookback Lens、CAD、DoLa；Lookback Lens 的检测部分回指 §3 |
| Selective generation / verify and revise | §5.4 修正与拒答 | SEAL 同时涉及训练；CoVe、CRITIC 使用验证信息指导输出修正 |

潜在原因与方法处在相同颜色列，只表示该阶段的文献归纳，不表示某篇论文已证明该原因，也不表示对应方法可以保证消除它。混合方法在主讲位置详细介绍，其余位置交叉引用，不重复介绍全文。

反馈协议：**原输出 y → 机制干预 → 新输出 y′ → 相同参照、数据与协议下复评 → 同时检查有用覆盖、拒答与成本 → 形成有条件的结论。** 这是综述用来审查已发表证据的规则，本项目没有新增模型实验。

每项“有效”判断应记录：模型/版本、任务与划分、来源语料、提示与生成预算、标注参照/粒度、评价器/版本、主要指标、输出长度、有用信息覆盖/拒答、计算或调用成本。研究缺报的维度标为未报告，不补造数值。

只有设置充分可比时才比较分数；否则比较机制与适用条件。不能因为少回答或全部拒答降低幻觉率，就直接结论“更好”；也不能将检测 F1 上升直接视为生成事实性提升。

## 7. 后续写作验收条件

1. 摘要、引言、Fig.2、正文标题与结论使用同一范围和 RQ；不扩展成未准备的多模态综述。
2. 每个关键技术结论有原论文证据；摘要筛选记录不能代替方法、消融、实验协议和局限的全文核验。
3. 每张图先在正文中交代问题，再解释其带来的结论，不逐字复述节点；每张表至少支持一个实质比较。
4. §3 明确“检测依据”；§4 明确“怎样评价依据是否可靠”；§5 明确“怎样干预”；§6 明确“何时有效、代价和缺口”。
5. 未来方向由前文具体不足导出，并说明可检验的问题，不只写更大模型、更多数据等笼统建议。
6. 用同一份最终 BibTeX 解决作者年份 a/b 后缀；图中内嵌引文、正文和参考文献必须一致。
7. ACL 主文实排后确认七页、四图一表均在主文、图表可读、核心分析没有被转移到附录。此项尚未开始。
